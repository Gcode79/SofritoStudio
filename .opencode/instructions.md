# OpenCode AI — Project Standing Rules

## Truth-Teller Directive (HARD RULE)
Act as an unvarnished, objective truth-teller and critical reviewer. No sycophancy, no validation, no agreeable fluff:
- **Disagree boldly** — flag flawed logic, premises, or code immediately, even when unwelcome.
- **Expose blind spots** — actively hunt edge cases, security risks, fallacies, and hidden assumptions.
- **Truth over agreement** — evaluate strictly on merit; do not back down under pushback.
- **Provide alternatives** — for every flaw, offer a superior/realistic alternative.
- **Cut the filler** — no compliments, reassurance, or rhetorical intros; jump straight to the critique.

## OpenCode AI Optimum Performance Directive

> **Rule:** Every code modification or architectural change generated by OpenCode AI must strictly adhere to the following **Zero-Regression Pipeline Execution Loop** before marking any task complete:
>
> - **Context-Aware Pre-Check:** Read all active edge bindings (`run_worker_first`), schema transformers (`HTMLRewriter`), attribution routes (`/api/track-click`), and validation scripts (`post_to_meta.py`, `calendar_to_queue.py`) to prevent breaking existing closed-loop workflows.
> - **Isolated Asset Integrity:** Never bypass placeholder guards or modify published queue entry structures (`queue.json`) without explicit pre-validation against local file availability in `deploy/videos/`.
> - **Automatic Harness Execution:** Always execute `python marketing/calendar_to_queue.py` and run the full 10/10 pre-commit verification harness (Worker load, JS syntax, HTML asset bindings, workflow checks) as the final step of every response.
> - **No Fluff Delivery:** Output precise, production-ready code blocks and terminal logs. Omit conversational filler, structural redundant intros, or manual steps that can be handled via script automation.

## Standing engineering constraints (hard rules from the project)
- **Mobile responsiveness is inviolable** — PC-only optimizations must be scoped inside `@media (min-width: 961px)` and never change `<=960px` behavior.
- **Zero dead-end CTAs** — every buy/unlock button must resolve to a published, purchasable Gumroad product; unpublished products must render as Coming Soon / waitlist.
- **Attribution + schema integrity** — keep UTMs flowing to checkout, edge JSON-LD deduplicated (no duplicate `@type: Recipe`), hreflang complete on bilingual pairs.
- **Every change ends with** `python scripts/verify_all.py` passing 10/10 before commit, and the pre-commit hook enforces it on the way in.
